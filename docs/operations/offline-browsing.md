# 离线浏览

离线功能面向普通百科浏览。首页、猫阵营、鼠阵营，以及导航图标和角色头像会主动准备；其他公共页面在访问后缓存。编辑、审核、管理、个人设置和通知页面不提供离线保证。缓存有容量和有效期限制，浏览器也可能回收存储，不能视为永久下载。

`scripts/offline-precache.mjs` 从构建后的首页、两个阵营页和离线提示页提取 JS/CSS，并递归保留懒加载依赖。Serwist 只预缓存这些文件和 `/offline/`，不批量下载所有页面、字体、地图切片或站内图片。离线提示页以 Next 构建 ID 标记版本，同一提交重新构建也会更新它。

Service worker 取得页面控制权后才开始准备内容，不再使用五秒超时。页面导航和 HTML 预热共用 `app-routes`；客户端导航后还会请求该页 HTML，以支持离线时的整页导航，并补齐所需的静态资源。私有页面/API 使用网络，RSC 数据与 HTML 分开缓存。

公共 HTML 最多保留 32 条、24 小时；运行时 JS/CSS 最多保留 200 条、24 小时。原有图片和地图切片缓存继续按需工作。头像预热尊重节省流量设置。

首次离线打开阵营页时，未曾在线加载的小型武器图标等按需图片可能缺失；头像预热不代表该页的所有图片都已下载。

修改后运行：

```powershell
node --test scripts/offline-precache.test.mjs
npm test -- --testPathPatterns="offlineWarmup|ServiceWorkerRegistration|sw.test|navigationUtils"
npm run lint
npm run type-check
npm run build:skip-images
```

浏览器验证必须使用生产构建。使用隔离的浏览器会话，等待 worker 控制页面及预热完成，关闭普通 HTTP 缓存后切换离线，避免 HTTP 缓存掩盖 Cache Storage 缺陷。检查：

1. 首次安装后，首页和两个阵营页均可显示，头像与交互正常。
2. 首次直接访问的详情页、经客户端导航访问的详情页，都可离线重新加载。
3. 未访问的页面显示离线提示，编辑/管理页面不返回缓存的私有内容。
4. 从上一版 worker 更新后，已打开的页面与新访问页面均正常；重新构建同一提交时离线提示页引用的资源也更新。

预缓存日志的 MB 数字是文件原始大小，不等于手机实际流量。比较优化时同时记录压缩体积和真实的首次安装请求；不要只检查 HTML 是否缓存，还需确认依赖的 JS/CSS 和图片可用。
