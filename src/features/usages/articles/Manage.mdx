# 网站管理指南

欢迎来到**猫鼠Wiki**。本文面向审核员（Reviewer，相当于维基百科的[巡查员](https://zh.wikipedia.org/wiki/Wikipedia:%E5%B7%A1%E6%9F%A5)+[回退员](https://zh.wikipedia.org/zh-hk/Wikipedia:%E5%9B%9E%E9%80%80%E5%8A%9F%E8%83%BD)）与协调员（Coordinator，相当于维基百科的[行政员](https://zh.wikipedia.org/zh-hk/Wikipedia:%E8%A1%8C%E6%94%BF%E5%91%98)），介绍文章、游戏数据、讨论和站点管理功能。\
交流群：**615882730**。

> 管理功能由权限控制，而不是只根据用户组名称判断。不同用户看到的标签、按钮和数据范围可能不同；如果下文提到的功能没有出现，请联系协调员确认权限。

## 进入管理功能

1. 登录网站。
2. 点击右上角头像，在菜单中选择“**进入管理面板**”。
3. 文章审核不在管理面板的标签中，进入**文章**板块后点击“**待审核**”，也可以直接打开 `/articles/pending/`。

管理面板的地址是 `/admin/`。页面会根据当前权限显示可用标签，常见标签包括“**改动审核**”“**用户管理**”“**用户组**”“**分类管理**”“**公告管理**”和“**封禁管理**”。

## MediaWiki 管理员快速上手

如果你熟悉 MediaWiki，可以先用下面的对应关系定位功能。这里的“对应”是工作目的相近，不代表底层实现完全相同。

| MediaWiki 中熟悉的概念 | 猫鼠Wiki 中的入口              | 需要注意的区别                                                                                        |
| ---------------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 用户组、用户权限       | `/admin/` → “用户组”“用户管理” | 使用权限组和权限范围控制功能；用户组可以继承父组，权限还可以限制到资源类型或指定资源。                |
| 编辑巡查、待处理编辑   | **文章** → “待审核”            | 文章编辑以待审核版本提交；“批准”会公开版本，“拒绝”会保留反馈，不使用 MediaWiki 式的巡查标记。         |
| 页面历史和版本差异     | 文章“**版本历史**”             | 可预览或比较文章版本；撤销操作针对当前已发布版本，并回退到上一已发布版本。                            |
| 模板或结构化数据的编辑 | `/admin/` → “改动审核”         | 游戏数据改动是独立的 JSON 操作队列，不与文章版本混在一起；审核时要查看字段路径、旧值和新值。          |
| 讨论页、Talk 页面      | 各内容的“**讨论**”页面         | 评论可以隐藏、显示或删除，且讨论管理权限可以按内容范围授予，不需要单独维护 Talk 命名空间。            |
| 用户/IP 封禁           | `/admin/` → “封禁管理”         | 除账号、IP 和 CIDR 外，还可以限制编辑、上传、创建账号或邮件功能，并设置资源范围、自动封禁和审计记录。 |
| 分类和分类维护         | `/admin/` → “分类管理”         | 分类的“默认可见性”还决定该分类下的编辑是直接公开、进入审核还是禁止修改，不只是页面归类。              |
| 站点公告、Site notice  | `/admin/` → “公告管理”         | 公告支持富文本、开始时间和结束时间，可以排期、取消发布或删除。                                        |
| 最近更改、公开编辑记录 | [最近更改](/recent-changes/)   | 这里只展示已通过审核的文章和游戏数据更改；待审核内容要分别去文章审核页或“改动审核”查看。              |

### 推荐的迁移顺序

1. 先打开 `/admin/`，确认自己拥有的标签；页面没有显示的功能通常是权限或权限范围问题。
2. 处理文章时先进入 `/articles/pending/`，处理结构化游戏数据时再进入“**改动审核**”。两者是两条独立的审核队列。
3. 用“**预览内容**”“**查看历史**”或改动详情中的差异确认提交，再执行批准、拒绝或撤销。
4. 需要管理用户、权限组、公告或封禁时，回到 `/admin/` 的对应标签；不要把文章审核页当作完整的管理后台。
5. 在“**通知**”中开启待审核提醒，之后可以从通知直接进入相应的处理入口。

## 审核前的通用原则

- 先看提交说明，再查看预览、版本历史或差异，不要只根据标题判断。
- 优先通过可以复核的内容：版本公告、游戏内实测、截图、视频或清晰的测试步骤。
- 拒绝时尽量填写具体反馈，指出需要修正的字段、事实或格式问题，方便提交者继续修改。
- 发现争议较大的结论时，可以先在对应讨论区或交流群沟通，再决定是否通过。

## 文章审核

### 查看待审核文章

进入“**文章**”板块，点击“**待审核**”。每条提交通常会显示：

- 标题、作者和编辑者；
- 文章分类及拟关联的角色；
- 提交时间和提交说明；
- 当前文章内容预览。

点击“**预览内容**”可以单独查看提交版本，点击“**查看历史**”可以了解文章的既有版本。审核时重点确认标题、分类、关联角色、正文事实、排版和站内链接是否合理。

### 批准或拒绝

对状态为“**待审核**”的文章，可以执行以下操作：

- **批准**：提交版本变为公开版本，文章前台同步更新。
- **批准并感谢**：批准文章，并向有账号的编辑者发送一条感谢通知。
- **拒绝**：不公开该版本。操作时可以填写审核反馈；建议说明具体修改方向。

审核结果会通过站内通知告知提交者。文章修改或新文章投稿的流程，参见[网站编辑指南](/usages/edit/)。

### 撤销已发布版本

如果已批准的版本后来被发现有严重错误，可以打开文章的“**版本历史**”，在当前已发布版本旁点击“**撤销版本**”。撤销后会回退到上一个已发布版本；如果没有更早的已发布版本，整篇文章将会被隐藏。

撤销只适用于当前已发布版本。请先查看版本差异，确认撤销对象没有选错。

## 游戏数据改动审核

### 筛选和查看改动

进入 `/admin/` 后打开“**改动审核**”。列表默认显示“**待审核**”改动。

点击改动右侧的展开按钮查看详情。详情会列出操作类型、字段路径以及旧值和新值；必要时可以复制改动 ID 或 JSON。差异较长时，可以切换“**显示全部上下文**”。

### 判断审核状态

| 状态   | 含义和处理方式                                     |
| ------ | -------------------------------------------------- |
| 待审核 | 尚未完成审核/复核。                                |
| 已批准 | 改动已进入公开数据。                               |
| 已拒绝 | 改动未公开，可以查看拒绝原因。                     |
| 已同步 | 改动已标记为同步到代码或基线，保留在历史记录中。   |
| 已撤销 | 改动已从公开数据 replay 中移除，保留在历史记录中。 |

有些改动会显示“**审核中但已公开**”。这表示改动已经公开，但需要进一步复核。

## 讨论内容管理

讨论管理不在 `/admin/` 的标签中，而是在各个内容的“**讨论**”页面进行。拥有对应讨论范围权限时，评论旁会出现管理按钮：

- **隐藏**：暂时不向普通访客展示，适合处理广告、跑题或需要进一步核实的内容；
- **显示**：恢复被隐藏的评论；
- **删除**：将评论标记为已删除。删除前请确认，界面不会提供恢复按钮。

## 分类管理

在管理面板打开“**分类管理**”。

### 创建分类

填写分类名称，选择父分类和默认可见性后点击“**创建**”。默认可见性有三种：

- **修改直接通过**：该分类下的编辑可以直接公开；
- **修改需要审核**：该分类下的编辑进入审核队列；
- **禁止修改**：不允许提交该分类下的改动。

### 编辑和删除分类

在现有分类列表中点击“**编辑**”可以修改名称、父分类和默认可见性。点击“**删除**”会永久删除分类；根分类不能删除。删除前请确认没有文章或其他数据依赖该分类。

分类默认可见性只决定后续改动的处理方式，不等于替审核员批准已有的待审核项目。

## 公告管理

拥有权限的 Reviewer 和 Coordinator 可以在管理面板打开“**公告管理**”。

### 发布或编辑公告

填写标题、内容、开始时间和可选的结束时间，然后点击“**发布公告**”。保存后立即发布；如果开始时间在未来，公告会自动处于排期状态，到时间后展示在首页。

公告列表会显示以下状态：

- **展示中**：当前正在首页展示；
- **待展示**：已发布但尚未到开始时间；
- **已过期**：已超过结束时间；
- **未发布**：已取消发布。

点击“**编辑**”可以修改公告。已过期或未发布的公告会显示“**编辑并重新发布**”。发布前检查开始、结束时间和富文本预览，避免把内部信息放到公开公告中。

### 取消发布和删除

- 已发布公告使用“**取消发布**”，不会再向访客展示；
- 未发布公告可以“**永久删除**”。删除不可恢复，确认对象无误后再操作。

## 用户管理（Coordinator）

在管理面板打开“**用户管理**”可以查看用户昵称及其用户组。

- 点击“用户组”下拉框，勾选或取消用户组即可更新分配；
- 点击“**编辑**”可以修改昵称；密码留空表示不修改密码；
- 修改用户或权限分配后，建议让对方重新加载页面，以便获取最新权限。

分配用户组会立即改变对方的可用功能。处理账号问题时，先通过用户昵称和个人主页确认目标用户，避免误改其他账号。

## 用户组和权限（Coordinator）

“**用户组**”用于集中管理权限。创建或编辑用户组时可以设置：

- 名称、说明和是否作为注册默认组；
- 要继承的父用户组；
- 每项权限的生效范围：全局、资源类型或指定资源。

子用户组会立即继承父组的全部权限，父组权限变化也会同步生效。继承部分显示为只读，需要回到来源用户组修改。

权限范围越大，影响的内容越多。建议按实际职责授予最小范围的权限，并在保存后检查用户组成员的实际可见标签。受保护用户组、默认用户组、有成员的用户组或仍有子用户组的用户组不能删除。

## 封禁管理（Coordinator）

“**封禁管理**”用于限制账号、IP 地址或 CIDR 网段的操作。创建封禁时需要填写理由，并选择限制范围和至少一项操作。

编辑限制还可以选择“**站点级**”或“**部分编辑资源**”。部分编辑需要进一步指定资源类型和资源 ID；其他操作目前按站点级限制处理。封禁可以设置到期时间，也可以设置为无限期。

活动封禁支持“**修改**”和“**解除**”。解除封禁必须填写理由；自动封禁记录不能直接修改。页面下方会保留封禁历史和审计记录，处理争议时请以这些记录为准。

封禁会影响提交、文章审核、分类、评论和游戏数据等写入操作。创建前确认目标、限制动作和到期时间，避免误伤正常用户。

## 通知和故障处理

拥有审核权限的用户可以在“**设置 → 通知设置**”中开启：

- 新待审核文章；
- 新待审核游戏数据改动。

如果看不到某个标签或操作按钮，可以依次检查：

1. 是否登录了正确账号；
2. 当前用户组是否拥有对应权限；
3. 权限是否只覆盖指定分类、数据类型或资源；
4. 账号是否存在“编辑内容”等封禁限制；
5. 刷新页面后是否仍然存在问题。

如果改动在审核过程中被其他人处理，或页面提示数据已变化，请先点击“**刷新**”，重新查看最新差异后再操作。持续出现权限或数据错误时，请保留页面提示、改动 ID 和操作时间，联系协调员或在交流群反馈。
